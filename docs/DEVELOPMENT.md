# 개발과 배포

집사(Zipsa)의 개발·데이터 저장·일정 규칙·배포 설정을 정리합니다. 모든 명령은 저장소 루트에서 실행합니다.

## 실행

Node.js 22.12 이상(권장 24 LTS), Rust 1.90 이상과 [운영체제별 Tauri 개발 도구](https://v2.tauri.app/start/prerequisites/)가 필요합니다. macOS에는 Xcode Command Line Tools, Windows에는 Visual Studio C++ Build Tools와 WebView2가 필요합니다.

```sh
npm ci
npm run desktop
```

`npm run dev`는 개발용 화면 서버만 실행합니다. 데이터 저장과 시스템 기능을 사용하려면 `npm run desktop`으로 실행하세요. 제품은 웹 서버 없이 설치된 앱 안에서 동작합니다.

## 기능과 동작

- 공간 트리: 최상위 공간 여러 개, 하위 공간 생성·수정·이동. 순환 관계와 내용물이 있는 공간의 삭제 방지.
- 아이템: 보관 공간, 수량·단위, 사진 한 장, 유통기한, 구매일·구매처·구매 금액(원), 메모. 사진은 최대 1600px로 줄여 저장하며 외부 파일 경로에 의존하지 않습니다.
- 할 일: 공간 또는 아이템 하나에 연결. 일회성, 날짜 기준 반복, 완료일 기준 반복. 일·주·월·년 단위와 간격 지원.
- 할 일별 미리 알림: 없음·10분 전·1시간 전·하루 전·일주일 전. 예정 시각 알림과 별도로 동작하며 실제 알림 시각을 편집기에서 확인합니다.
- 대형 월간 달력: 월 이동·오늘·방향키 탐색, 반복 예정 회차와 수행 기록 표시. 날짜별 오른쪽 패널에서 전체 일정 확인·완료·건너뛰기·취소·수정·할 일 추가.
- 오늘까지 할 일, 다가오는 일정, 유통기한 확인, 전체 검색, 완료·건너뛰기 이력. 할 일 목록에서 바로 삭제할 수 있고 기존 수행 기록은 유지합니다.
- 라이트·다크 화면 테마. 설정에서 고르거나 운영체제 설정을 따르며, 상단 바의 버튼으로 바로 전환할 수 있습니다. 선택은 이 컴퓨터에만 저장하고 백업에는 포함하지 않습니다.
- 창을 닫으면 메뉴 막대·트레이에 상주. 설정에서 알림과 로그인 시 자동 실행 활성화. 완전히 종료하려면 트레이의 **집사 종료**를 선택하세요.
- 사진과 수행 기록을 포함하는 `.zipsa` 백업·복원. 복원 전 현재 데이터를 자동 백업하고, 검증과 트랜잭션으로 잘못된 복원이 기존 데이터를 지우지 않도록 합니다.
- 자동 백업: 내용이 바뀐 날 하루 한 번 앱 데이터 폴더에 백업하고 최근 7개를 보관합니다. 설정에서 마지막 백업 시각을 확인하고 백업 폴더를 열 수 있습니다.
- 앱에서 최신 버전과 변경 내용을 확인하고 GitHub 다운로드 페이지로 이동.

설정의 **할 일 알림**을 켜서 OS 알림 권한을 허용하세요. 백그라운드 프로세스가 30초마다 예정 시간을 확인합니다. 컴퓨터가 꺼져 있거나 잠들었거나 앱을 완전히 종료한 동안에는 알림을 보내지 않으며, 다음 실행·절전 해제 때 미처리 일정을 확인합니다. 미리 알림과 예정 시각 알림은 각각 회차별 한 번 보내고, 같은 종류가 여러 개 밀렸으면 묶어서 보냅니다. 예정 시각이 이미 지났으면 미리 알림을 함께 보내지 않고 예정 시각 알림만 보냅니다.

미리 알림은 확정된 다음 예정일을 기준으로 계산합니다. 하루 전은 24시간, 일주일 전은 168시간 전입니다. 내용만 수정하면 이미 보낸 알림은 다시 보내지 않으며, 예정일·활성 상태 변경이나 완료 취소 시 해당 회차의 알림 상태를 초기화합니다. 미리 알림 간격 변경은 미리 알림 상태만 초기화합니다. 새 회차가 만들어졌을 때 미리 알림 시각이 이미 지났고 예정 시각은 아직 남았다면 다음 확인 때 미리 알려줍니다.

## 일정 규칙

날짜 기준 반복은 최초 예정일과 시간대를 기준으로 계산합니다. 1월 31일의 월간 일정은 2월 말일을 거쳐 3월 31일로 돌아옵니다. 늦게 완료한 경우 지나간 회차는 누적 생성하지 않고 다음 미래 회차로 이동합니다. 미완료 회차는 처리 전까지 ‘오늘까지’에 남습니다.

완료일 기준 반복은 실제 완료 시점부터 간격을 계산합니다. ‘건너뛰기’도 처리한 시점을 기준으로 다음 회차를 만듭니다. 일회성 일정을 완료하거나 건너뛰면 비활성화됩니다. 처리 기록은 할 일을 삭제해도 유지합니다.

종료된 할 일의 체크 버튼을 다시 누르거나 수행 기록의 **완료 취소**를 누르면 미완료로 되돌릴 수 있습니다. 가장 최근 회차부터 취소하며, 해당 기록을 제거하고 이전 예정일을 복원합니다. 반복 규칙과 기준일, 이후 수정한 이름·메모는 유지합니다. 처리 후 예정일이나 반복 규칙을 바꿨다면 이를 덮어쓰지 않고 할 일 수정에서 직접 변경하도록 안내합니다. 기존 버전에서 생성한 완료 기록도 취소할 수 있습니다.

## 달력

달력은 이 컴퓨터의 현지 시각과 예정일을 기준으로 표시합니다. 수행 기록은 실제 완료일 대신 원래 예정일에 놓고, 상세에서 실제 완료·건너뛴 시각을 함께 보여줍니다. 삭제된 할 일의 기록도 남습니다. 미리 알림 날짜는 달력에 별도 일정으로 만들지 않고 상세에서 확인합니다.

날짜 기준 반복은 기존 일정 계산기로 미래 회차를 미리 표시합니다. 현재 회차가 밀려 있어도 미래 예상 날짜는 볼 수 있으며, **현재 회차 보기**로 이동해 처리합니다. 반복 예정 회차의 완료 버튼은 제공하지 않으며 현재 예정일과 일치하는 회차만 처리할 수 있습니다. 반복 할 일 수정은 전체 반복 규칙을 수정합니다. 완료일 기준 반복은 실제 완료 시점에 다음 날짜가 정해지므로 확정된 다음 회차만 표시합니다. 달력을 조회해도 저장된 예정일은 바뀌지 않습니다.

키보드는 방향키로 날짜 이동, Home·End로 주의 처음·끝 이동, Page Up·Down으로 월 이동, Enter로 날짜별 패널 열기를 지원합니다. 화면에는 날짜당 최대 두 일정을 표시하고 나머지는 **더 보기**로 엽니다.

## 데이터

데이터베이스 파일은 OS의 앱 데이터 폴더 아래 `app.zipsa.desktop/zipsa.sqlite`에 저장합니다. 실제 경로는 앱의 **설정 → 내 데이터와 백업**에서 확인할 수 있습니다. 앱 잠금과 별도 데이터 암호화는 적용하지 않습니다.

사진은 같은 SQLite 파일의 `photos` 테이블에 원본 바이트로 저장하고, 아이템 데이터에는 사진 식별자만 둡니다. 화면은 앱 전용 주소(`zipsa-photo://localhost/식별자`, Windows는 `http://zipsa-photo.localhost/식별자`)로 표시할 사진만 불러옵니다. 그래서 저장·조회 때마다 오가는 데이터에 사진이 포함되지 않습니다. 사진을 바꾸면 새 식별자를 만들고 이전 사진은 지웁니다. 아이템을 삭제하면 사진도 함께 삭제합니다. 사진은 JPEG·PNG·WebP 형식으로 3MB까지 저장할 수 있으며, 형식은 파일의 실제 내용으로 확인합니다.

현재 스키마는 v2입니다. v1(0.2.0 이하) 데이터는 처음 실행할 때 아이템 데이터 안의 사진을 `photos` 테이블로 옮깁니다. 옮기기 전에 원래 데이터를 `backups/before-upgrade-v1-날짜.zipsa`로 남깁니다. 손상되어 읽을 수 없는 사진은 옮기지 않으며, 이 파일에는 그대로 남아 있습니다. v2 데이터는 이전 버전 앱에서 열 수 없습니다. 스키마를 바꿀 때는 `src-tauri/src/store.rs`의 `SCHEMA_VERSION`을 올리고 마이그레이션을 추가하세요.

백업 `.zipsa` 파일은 사진을 포함한 데이터베이스 전체를 압축한 SQLite 사본입니다. 플랫폼과 관계없이 복원할 수 있고 크기 제한이 없습니다. 0.2.0 이하에서 만든 JSON 형식 백업(최대 256MB)도 복원할 수 있습니다. 새 형식의 백업은 0.2.0 이하 앱에서 복원할 수 없습니다. 복원할 때는 선택한 파일을 임시 사본으로 열어 검증합니다. 집사가 만든 데이터베이스가 아니거나 손상된 파일은 거부하고, 현재 데이터는 한 트랜잭션 안에서 교체합니다. 복원 직전 데이터는 `backups/before-restore-날짜.zipsa`에 보관합니다.

자동 백업은 앱이 실행 중일 때 시작 1분 후부터 1시간마다 확인합니다. 마지막 자동 백업에서 24시간이 지났고 그 뒤로 내용이 바뀌었으면 `backups/auto/Zipsa-auto-날짜-시각.zipsa`를 만들고 최근 7개만 남깁니다. 알림 발송 상태처럼 사용자가 수정하지 않은 변경은 내용 변경으로 보지 않습니다. 데이터가 비어 있으면 백업하지 않습니다. 자동 백업은 같은 컴퓨터에 있으므로 저장 장치 고장에 대비하려면 **백업 내보내기**로 다른 장치에 보관하세요. 복원 창은 자동 백업 폴더에서 열립니다.

데이터베이스 파일을 직접 복사하려면 앱을 완전히 종료하세요. 기본 제공 클라우드 동기화·원격 분석·외부 이미지 로딩은 없습니다. 사용자가 선택한 백업 경로가 클라우드 동기화 폴더라면 해당 OS 서비스의 정책을 따릅니다.

## 검증

```sh
npm run build
npm test
npx playwright install chromium
npm run test:ui
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
npm run tauri -- build --debug --bundles app  # macOS
```

Rust 테스트는 공간 관계, 복원 검증, 회차 중복 완료, 기록 보존과 반복 일정의 월말·시간대 처리를 확인합니다. v1 데이터 변환, 사진 저장·교체·삭제, 새 형식과 이전 JSON 형식 백업의 복원, 자동 백업 주기와 보관 개수도 확인합니다. UI 테스트는 IPC를 대체한 Chromium에서 입력·탐색·검색 흐름을 확인하며, 실제 OS의 알림·자동 실행이나 설치 후 업데이트를 대신 검증하지 않습니다. CI는 macOS와 Windows에서 Rust 테스트와 데스크톱 빌드를 실행합니다.

## GitHub 빌드와 배포

`.github/workflows/ci.yml`은 `main` 푸시와 PR에서 검증을 수행합니다. `release.yml`은 `v0.1.0` 같은 태그에서 Apple Silicon Mac의 DMG와 Windows x64 설치 EXE를 빌드합니다. 두 설치 파일이 모두 업로드되었는지 확인한 뒤 GitHub Release를 공개합니다. 지원 환경은 macOS 13 이상(Apple Silicon), Windows 10 이상(x64)입니다.

README의 `/releases/latest`와 `/releases/latest/download/파일명` 링크는 최신 정식 릴리스를 가리킵니다. 설치 파일명은 `Zipsa-macOS-arm64.dmg`, `Zipsa-Windows-x64.exe`로 고정하고 버전별 릴리스에서 각각 보관합니다. 빌드 중에는 기존 최신 버전이 유지되며, 모든 플랫폼의 빌드가 성공하면 더 높은 버전의 릴리스를 최신으로 지정합니다. `latest`라는 별도 Git 태그는 만들지 않습니다.

앱 내 자동 설치를 사용하지 않으므로 업데이트 전용 서명 키와 `latest.json`은 필요하지 않습니다. 새 버전 배포 시 `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`의 버전을 함께 변경하고 일치하는 `v버전` 태그를 푸시합니다.

macOS 외부 배포의 코드 서명·공증에는 별도의 Apple 개발자 자격이 필요합니다. 다음 선택 설정을 릴리스 워크플로가 지원합니다.

| 종류     | 이름                         | 값                                           |
| -------- | ---------------------------- | -------------------------------------------- |
| Secret   | `APPLE_CERTIFICATE`          | Base64로 인코딩한 Developer ID 인증서 `.p12` |
| Secret   | `APPLE_CERTIFICATE_PASSWORD` | 인증서 암호                                  |
| Variable | `APPLE_SIGNING_IDENTITY`     | Developer ID Application 서명 이름           |
| Secret   | `APPLE_ID`                   | 공증에 사용할 Apple ID                       |
| Secret   | `APPLE_PASSWORD`             | 앱 전용 암호                                 |
| Variable | `APPLE_TEAM_ID`              | 개발자 팀 ID                                 |

`APPLE_CERTIFICATE`와 `APPLE_SIGNING_IDENTITY`가 모두 없으면 릴리스 워크플로가 macOS 앱을 ad-hoc 서명합니다. 서명하지 않은 앱 번들을 인터넷에서 받으면 macOS가 손상된 앱으로 판단해 열 수 없기 때문입니다. ad-hoc 서명한 앱은 공증되지 않았다는 경고를 표시하고, 사용자가 허용하면 실행됩니다. 공증에는 Developer ID가 필요하므로 이때는 공증 자격 증명을 내보내지 않습니다. 인증서나 서명 이름을 등록하면 ad-hoc 서명 대신 Developer ID로 서명하고, 공증 자격 증명이 있으면 공증합니다. 사용자용 허용 절차는 README의 [처음 실행할 때](../README.md#처음-실행할-때)에 있습니다.

OS의 앱 코드 서명과 공증은 별개입니다. Apple 자격이 없으면 일반 사용자 배포용 공증이 되지 않으며, Windows 코드 서명도 현재 워크플로에 포함하지 않았습니다. 공개 배포 전에 실제 설치 환경에서 OS 서명·권한·알림을 확인해야 합니다. [macOS 서명](https://v2.tauri.app/distribute/sign/macos/), [Windows 서명](https://v2.tauri.app/distribute/sign/windows/).

## 버전 확인과 다운로드

앱을 시작할 때 한 번 GitHub의 공개 Releases API에서 최신 정식 릴리스를 조회합니다. 새 버전이 있으면 화면 상단에 버전과 **새 버전 다운로드** 버튼이 있는 알림을 표시합니다. 알림을 닫으면 실행 중에는 다시 띄우지 않고 다음 실행 때 다시 확인합니다. 로그인 시 자동 실행으로 창이 숨겨져 있으면 창을 열 때 알림을 볼 수 있습니다. 이 알림은 앱 안에서 표시하므로 OS의 할 일 알림 설정과 관계없이 확인할 수 있습니다.

설정의 **최신 버전 확인**은 별도로 새 요청을 보내므로 시작 시 확인에 실패했거나 실행 중 새 릴리스가 나온 경우에도 사용할 수 있습니다. Semantic Versioning으로 현재 앱과 버전을 비교하고, 새 버전이 있으면 변경 내용과 **다운로드 페이지로 이동** 버튼을 표시합니다. 버튼은 기본 브라우저로 GitHub의 최신 릴리스 페이지를 엽니다. 설치 파일 다운로드와 설치는 사용자가 직접 진행합니다.

초안·프리릴리스는 업데이트로 안내하지 않습니다. 시작 시 확인 실패는 앱 로딩을 지연시키거나 오류 알림을 띄우지 않습니다. 수동 확인에서는 공개 릴리스 없음·인터넷 연결 실패·GitHub 요청 제한을 안내하고 릴리스 목록을 직접 열 수 있습니다. 조회에 공간·아이템·사진·할 일 데이터와 GitHub 인증 토큰을 보내지 않습니다.

조회 주소와 허용된 다운로드 페이지는 `src-tauri/src/updates.rs`에 정의합니다. 포크한 앱을 별도로 배포할 경우 해당 프로젝트의 주소로 변경하세요. 앱 데이터 폴더는 설치 파일과 분리되어 있습니다. 스키마 버전과 마이그레이션은 [데이터](#데이터)를 참고하세요.

## 의견 수집

설정에서 Google Forms를 여는 기능과 폼 생성 스크립트를 제공합니다. [의견 수집 폼 연결](FEEDBACK.md)에 따라 폼을 생성하고 `feedback.config.json`을 설정하면 앱에 **의견 보내기**가 표시됩니다. 브라우저를 열 때 앱 버전과 운영체제 이름만 미리 채우며, 의견 내용과 이메일은 폼에서 직접 작성합니다. API 키나 서버는 필요하지 않습니다.
